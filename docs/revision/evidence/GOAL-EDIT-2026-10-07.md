# Goal definition edit — 2026-10-07

## Outcome and scope

The goal detail route lets a user edit the title and target value of an active,
current-period goal. The write preserves goal identity, type, period, period
boundaries/time zone, status and session-derived progress. It adds no schema
fields and does not alter goal-calculation semantics. Focus-time targets are
entered/displayed in minutes and remain stored as seconds. An unchanged target
preserves the exact stored seconds, including values that are not whole minutes.

Only a verified local owner store may perform the conditional SQLite update.
The write requires the goal's loaded `updatedAt`, and accepts only active goals
that are not legacy open-period records. A stale revision is refused; a failed
write keeps the user's draft for retry. The route does not mutate completion,
period, start/end, timezone or status fields.

## Acceptance and risk

- Session-count targets must be positive safe integers.
- Focus-time minute input converts to a positive safe integer number of seconds.
- Writes preserve owner isolation and advance revision timestamps even when the
  injected clock returns the same millisecond.
- Existing goals, task links and focus history are not deleted or rewritten.
- Failed/stale writes do not replace the displayed saved definition.

Risk is HIGH provisionally because this edits persisted account-owned goal data.
Implementation remains `REVIEW_PENDING` until an independent reviewer checks
owner scoping, stale-write behavior and compatibility with the canonical data
contract. Android device, keyboard, accessibility and real native SQLite checks
are `NOT_RUN`. This evidence does not claim production readiness.
