# Deep Focus: වෙළඳපොළ, පරිශීලක අවශ්‍යතා සහ නිෂ්පාදන දිශාව

## 1. ප්‍රධාන නිගමනය

Deep Focus සඳහා හොඳ අවස්ථාවක් තිබේ. නමුත් එය apps 20ක features එකතු කළ “හැමදේම කරන app එකක්” වීම නොවේ. වඩා ශක්තිමත් දිශාව වන්නේ **වැඩක් පැහැදිලිව පටන්ගන්න, බාධා අඩුවෙන් කරගෙන යන්න, නතර වූ තැනින් පහසුවෙන් නැවත පටන්ගන්න** උදව් කරන calm, trustworthy productivity product එකක් වීමයි.

මගේ නිර්දේශය: reliable focus-session engine එක මූලික කරගෙන, පසුව **Return Ticket / Context Bridge** නම් කුඩා continuity workflow එක ප්‍රධාන වෙනස්කම ලෙස validate කරන්න. Timer එක නතර වුණත්, වැඩේ ගැන හිතේ තිබුණු context එක නැති නොවීම මෙහි වටිනාකමයි. මෙය තහවුරු කළ market gap එකක් හෝ “ලෝකයේ පළමුවැනි feature එක” බවට ප්‍රකාශයක් නොවේ; පරීක්ෂා කළ යුතු product hypothesis එකකි.

අද තත්ත්වයේ වැදගත්ම දේවල් පහ:

1. **Code එක functional local prototype / early foundation මට්ටමේය; production-ready V1 නොවේ.** Screens තිබීමෙන් authentication, AI, verified rewards හෝ cloud recovery ඉවර වී ඇති බව අදහස් නොවේ.
2. Session එක කලින් complete කිරීම සහ save කිරීමේ failure paths මුලින්ම විසඳිය යුතුය. වැරදි history එකක් මත analytics, goals සහ rewards ගොඩනැගීමෙන් ගැටලුව වැඩි වේ.
3. Reviews වල බලවත් themes වන්නේ reliability, low-friction setup, fair pricing, predictable controls සහ අඩු product-generated interruptions ය. මේවා statistical prevalence estimates නොව, තෝරාගත් review sample එකේ recurring signals ය.
4. AI, ambient sound, gamification, energy planning, app blocking සහ body doubling දැනටමත් තරගකරුවන් සතුව තිබේ. ඒවා තනිවම uniqueness නොවේ.
5. Enterprise දිශාව විය යුත්තේ **කණ්ඩායමක focus time ආරක්ෂා කිරීම** මිස, පුද්ගලයෙකු “කොච්චර productive ද” කියා boss කෙනෙකුට ලකුණු දෙන surveillance dashboard එකක් නොවේ.

මෙම report එකේ market observations 2026-09-13 දිනට ලබාගත් public sources මත පදනම් වේ. “හොඳම 20” යන්න global ranking එකක් නොව Deep Focus සඳහා විශේෂයෙන් ප්‍රයෝජනවත් benchmark set එකකි. Exact prices වෙනුවට බොහෝ තැන්වල business model සඳහන් කරන්නේ region, store සහ billing period අනුව මිල වෙනස් වන නිසාය.

User කැමති නම් focus පසුව “දැන් තෙහෙට්ටුද?” වැනි සරල self-report එකක්. තමන් තෝරාගත් break lengths/activities සමඟ සති කිහිපයක් patterns බලයි. “ඔබේ දත්ත අනුව මේ pattern එක දක්නට ලැබෙනවා; වෙනත් හේතු තිබිය හැක” ලෙස සීමා සහිත explanation ලබාදෙයි.

Structured energy planning සහ Endel recovery contexts දැනටමත් ඇත. මෙහි hypothesis එක transparent, local-first personal experiment එකයි. Break research well-being benefits සඳහා සහාය දක්වන නමුත් cognitive performance සෑම අවස්ථාවකම වැඩි වන බව හෝ universal ideal duration එකක් සනාථ නොකරයි.[^37] No burnout diagnosis, no forced stop, no wearable requirement.

### 7.5 Graceful Return — streak එක කැඩුණත් නැවත එන්න පහසු වීම

Rest days, planned working days සහ comeback message එකක්. Missed day එකකදී earned history/XP මකා දැමීම නැත. “ඔබ අසාර්ථකයි” වෙනුවට “ඊළඟ කුඩා පියවර මොකක්ද?” කියයි.

මෙය unique invention එකක් නොවේ; Deep Focus brand principle එකේ implementation එකකි. Default leaderboard නැතිව personal consistency සහ meaningful weekly progress පෙන්වන්න. Metric: lapse පසු return rate සමඟ guilt/pressure feedback. Engagement වැඩි කිරීමට overwork දිරිගන්වනවා නම් design එක අසාර්ථකය.

### 7.6 Focus Passport — context සමඟ cross-device continuation

Phone එකේ plan කර laptop එකේ වැඩ කිරීම, නැවත phone එකේ break/summary ලබාගැනීම. Timer sync දැනටමත් competitors සතුව තිබේ; අපේ hypothesis එක task context, Return Ticket සහ ownership-safe single active session එක එකට ගෙන යාමයි.

මෙය post-V1 complexity වැඩි වැඩකි: device leases, offline conflicts, idempotency, clock differences, privacy සහ restore tests අවශ්‍යය. මුලින් same-device reliability, පසුව explicit transfer. Silent duplicate sessions හෝ double rewards ඇති විය නොහැක.

### 7.7 Attention Contract — session එක තුළ product එකත් නීති පිළිපැදීම

Session setup එකේ සරල agreement එකක්: මේ කාලය තුළ product prompts/ads නැත; AI suggestions defer වේ; user-approved exceptions පමණි. Session අවසානයේ aggregate interruption summary එකක් තිබිය හැක; private notification contents අවශ්‍ය නැත.

මේවායේ කොටස් approved docs තුළත් ඇත; සම්පූර්ණයෙන් අලුත් invention එකක් නොවේ. එය visible, testable brand promise එකක් කිරීම වෙනස්කම විය හැක. Metric: product-caused interruption count, user understanding සහ opt-out clarity. OS එක හරහා සියලු external interruptions නතර කළ හැකි බව නොකියන්න.

## 8. මුල් users, positioning සහ වෙළඳපොළට පිවිසීම

**පළමු cohort එක:** දිගු study/work tasks කරන, interruption පසු නැවත ආරම්භ කිරීම අමාරු students හෝ independent knowledge workers. මේ දෙපිරිසම එකවර market නොකර, ඔබට සෘජුව interview/test කළ හැකි එක් කණ්ඩායමක් මුලින් තෝරන්න. “හැමෝම productive කරන්න” යන්න test කළ හැකි customer definition එකක් නොවේ.

Proposed positioning sentence:

> Deep Focus helps you start clearly, work quietly, and return easily—without turning productivity into pressure.

මෙය නව brand copy proposal එකකි; ඔබේ දැනට තෝරා ඇති **“Focus on What Matters.”** tagline එක වෙනස් කිරීමක් නොවේ.

**Initial acquisition hypothesis:** study communities, independent-work communities සහ small creator/education partnerships හරහා problem-first demonstrations. “අලුත් Pomodoro timer” කියන demo එක වෙනුවට interrupted task එකකට Return Ticket එකෙන් නැවත පිවිසෙන කුඩා before/after walkthrough එකක් පෙන්වන්න. Outcomes තහවුරු වීමට පෙර productivity percentages ප්‍රචාරය නොකරන්න.

**Retention hypothesis:** app එක තුළ වැඩිපුර කාලය ගත කිරීම නොව, user විසින් තෝරාගත් වැඩ දිනවල reliable meaningful sessions සහ unfinished work continuation. Notification volume, daily compulsory streaks සහ reward chasing retention strategy එක නොවිය යුතුය.

මෙම විමර්ශනය market-size estimate, revenue forecast හෝ statistically representative willingness-to-pay survey එකක් නොවේ. Competitor presence සහ reviews මගින් problem/value patterns පෙනේ; ඔබට ලැබෙන market share හෝ enterprise demand තහවුරු නොවේ. ඊළඟ සාක්ෂිය real users සහ paid pilot behavior විය යුතුය.

## 12. Roadmap: අලුත් දේවල්ට පෙර විශ්වාසදායක V1

මේ roadmap එක approved phase order වෙනස් නොකරන prioritization recommendation එකකි. Existing implementation plan හි checkpoint 2026-11-15, beta 2026-11-30, submission 2026-12-15 සහ V1 release 2027-01-01 යන target dates ඇත. ඒවා දැනටමත් achieved බව හෝ මේ report එකෙන් guaranteed බවක් නොවේ.

### Gate A — සත්‍ය baseline සහ foundation

README / implementation checklist / changelog status එක owner review කර align කරන්න. Already-built local flows සහ unmet acceptance gates වෙන් කරන්න. Provider/auth decisions, architecture boundaries, reusable tokens සහ minimum automated verification foundation තහවුරු කරන්න. Userගේ pending home/token edits රැකගන්න.

### Gate B — authentication සහ trustworthy session vertical slice

Approved authentication/user foundation පසු core flow එක සම්පූර්ණ කරන්න: configure → start → supported pause/resume → complete/cancel → durable persist → recover → verified progress. Early completion semantics, task association, hydration gating සහ save errors මුල් acceptance cases කරගන්න. Full required duration නොමැති session එක completed ලෙස mark නොකරන්න.

### Gate C — tasks/goals/progress සහ settings

Stable task identity, explicit completion, calendar-bound goals/streaks, trusted reward rules, useful basic analytics සහ settings/a11y. Rewards හි correctness සහ humane behavior දෙකම බලන්න. Break completion/skip/early end සහ summary order canonical spec එකට ගැළපිය යුතුය.

### Gate D — approved assessment සහ AI

Assessment answers persist කර truthful profile generation කරන්න. **Plan My Day delivery එක approved V1 requirement එකකි**, නමුත් user ට AI භාවිත කිරීම optional ය; core focus සඳහා AI අවශ්‍ය නොවේ. Current deterministic prototype එක actual AI ලෙස label නොකරන්න. Minimal context, proposal validation, explicit exact-action confirmation, quota, trusted ad grant verification සහ safe failures අවශ්‍යය.

### Gate E — sync/recovery, release hardening සහ real-device evidence

Offline transitions, storage faults, process death, background/foreground, interrupted breaks, clock changes, duplicate actions, account boundaries සහ deletion/export flows verify කරන්න. iOS/Android, screen readers, large text, reduced motion, keyboard/focus behavior සහ battery impact පරීක්ෂා කරන්න. UI screenshots පමණක් release evidence නොවේ.

### Gate F — පළමු differentiation experiment

Core gates සහ owner scope approval පසු **Return Ticket පමණක්** limited cohort එකකට pilot කරන්න. ලාභදායී signal ලැබුණොත් Outcome Receipt/Graceful Return සමඟ refine කරන්න. Shield, wearable-based adaptation, cross-device passport සහ team platform එක එකවර නොගන්න.

**Release-blocking test examples:** start කර ඉක්මනින් Complete tap කිරීම; storage-full/history-write failure; save අතර app kill කිරීම; rapid pause/resume; duplicate terminal action; completed task rename/delete; Sunday→Monday goal rollover; timezone change; paused session relaunch; break අතර process death; offline→online duplicate sync; denied permissions; 200% text size.
